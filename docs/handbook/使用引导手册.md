# 申万行业估值仪表盘｜使用引导手册

> GitHub 分发提示（2026-09-14）：本手册的便携启动步骤适用于另行取得的已构建运行包。此仓库只提供维护代码和文档，不包含便携 ZIP、行情数据或凭据；GitHub Download ZIP 不是便携包。源码使用与缺件说明见[仓库 README](../../README.md)及[发布范围](../PUBLICATION_SCOPE.md)。正文核对日期与历史验收边界保持不变。

适用版本：应用 v2.3.0，便携包 `2.3.0-portable.1`。文档核对日期：2026-09-09（北京时间）。

这份手册面向第一次使用的人，不要求会编程。维护、改功能和重新打包请看同目录的[工程交接文档](工程交接文档.md)。

**先记住三件事：完整解压对应平台的包 → 双击启动文件 → 在 Chrome 打开本机地址。** 不需要另装 Python、pip 或 Node。

本版是本地研究工具，不是交易软件。行业估值位置不等于投资建议；页面没有下单、自动选股、回测或定时更新功能。

> 本手册是单独交付的说明文件，请放在便携包文件夹旁边。不要把它、新截图或其他普通文件直接放进已经解压的便携包内部：程序会核对文件库存，额外文件也可能导致启动失败。不要修改包内清单来绕过检查。

## 1. 先选对版本

总包 `SWIVD-2.3.0-portable.1-all-platforms.zip` 只是装着三个平台包的外层容器。解开总包后，还要解压你要使用的那个平台 ZIP；无需解压另外两个。

| 你的电脑 | 选择的文件 | 双击哪个文件 |
| --- | --- | --- |
| Mac，芯片为 Apple M 系列 | `SWIVD-2.3.0-portable.1-macos-arm64.zip` | `Start-Mac.command` |
| Mac，处理器为 Intel | `SWIVD-2.3.0-portable.1-macos-x86_64.zip` | `Start-Mac.command` |
| Windows 10/11，x64 处理器 | `SWIVD-2.3.0-portable.1-windows-x86_64.zip` | `Start-Windows.cmd` |

Mac 可在苹果菜单的“关于本机”查看芯片或处理器。不要因为都叫 Mac 就混用 ARM 和 Intel 运行时。Windows ARM64 原生、32 位 Windows 和 Windows 7/8.1 不在本版范围。

兼容性说明：Mac ARM 的编译目标下限是 macOS 11，Intel Mac 是 macOS 10.15；这不是所有旧系统都已实测的保证。已有 Mac ARM 原生验收，以及另一台 macOS 26.6.2 的用户启动成功反馈；Intel Mac 和 Windows 仍缺少对应真机完整验收。

## 2. 五分钟完成第一次启动

### 2.1 放好文件

1. 把对应平台 ZIP 完整解压到自己的本机可写目录。
2. 保留整个 `SWIVD-2.3.0-portable.1-平台名` 文件夹，不要只拿出一个启动文件。
3. 先不要放到网盘同步目录、系统目录、只读移动盘或过深的路径。Windows 推荐短路径，例如 `C:\SWIVD`。Mac 若桌面由 iCloud 同步，改用未同步的本机目录。
4. 不要在 ZIP 预览中运行，也不要双击 `app/web/index.html`。后者只是网页源码，不是运行入口。

正常的文件夹里应能看到启动文件、`launcher.py`、`runtime`、`packages`、`app`、`seed-data` 和 `package-manifest.json`。Windows 若隐藏扩展名，启动文件可能只显示 `Start-Windows`。

### 2.2 双击启动

- Mac：双击 `Start-Mac.command`。
- Windows：双击 `Start-Windows.cmd`。

会打开一个终端或命令窗口。程序先校验包和冻结数据，再在本实例内准备运行数据；首次可能需要数十秒，也可能因磁盘或电脑速度更久。请保留窗口，等明确的启动结果，不要连续双击开启多个实例。

### 2.3 处理 Token 提示

程序依次寻找：

1. 当前启动进程继承的 `TUSHARE_TOKEN` 环境变量；
2. 这台电脑上 Tushare SDK 已保存的 Token；
3. 若前两者均没有，终端提示你临时输入。

有自己的 Token 时，粘贴后按回车。**输入不显示字符或星号是正常现象**，不是键盘失效。

暂时没有 Token：在提示处直接回车，可以先浏览随包提供的冻结数据。本版初始数据截至 **2026-09-04**，不是今天的数据。以后想联网更新，可在作业结束后停止程序，再启动并输入有效 Token。

若你没有输入就直接启动，且没有“未配置 token”提示，按本版逻辑说明程序已找到非空 Token；不能仅凭这个现象判断来源，更不能证明 Token 有效或接口权限足够。

获取 Token 可登录自己的 Tushare 账户，进入个人中心的“账号与TOKEN”。具体操作以[Tushare 官方获取凭证说明](https://tushare.pro/document/1?doc_id=39)为准。本软件不会提供账号，也不会替你购买权限。不同接口的权限、频次和发布时间以你的账户与官方说明为准。

安全要求：不要把 Token 发给维护者或 Agent，不要粘贴进网页、聊天、启动命令参数、截图或日志。通过终端临时输入的 Token 只供此次进程使用，程序不将其写入配置或系统；已有 SDK 配置不会因此被删除或改写。

### 2.4 打开页面

看到类似下面的输出，表示本机服务已开始监听：

```text
{"status": "SERVING", "url": "http://127.0.0.1:8765"}
```

在**同一台电脑**的 Chrome 中打开：

[http://127.0.0.1:8765](http://127.0.0.1:8765)

程序不会自动打开浏览器。`127.0.0.1` 指正在使用的这台电脑，不能把这个地址发给另一台电脑或手机来访问此实例。服务不向局域网开放。

`SERVING` 只证明服务启动，不证明网页已正常加载、Token 可用或数据更新成功。首次页面读取快照还可能执行完整校验，请等待页面顶部显示快照日期和行业内容。

### 2.5 确认真的可以用了

- 页面是深色仪表盘，能看到顶部快照日期。
- 切换 L1、L2、L3 时，可以看到对应层级的行业。
- 在“行业成分”选择一个行业，能看到行业说明或明确的无数据状态。
- 首次未联网更新时，日期仍为 2026-09-04，这是预期状态。

以上属于浏览确认，不能替代后面的联网更新确认。

## 3. 页面怎么读

先看顶部“正在浏览哪一个日期的快照”，再看行业层级，最后看具体图表。**浏览历史快照时，页面不是实时行情。**

| 页面入口 | 主要用途 | 阅读时注意 |
| --- | --- | --- |
| 总览 | 比较当前层级各行业的 PE/PB 历史位置和分布 | 比较的是各行业相对自身历史的位置，不是统一内在价值 |
| 估值热力图 | 用 PE 或 PB 历史百分位着色，快速找出位置差异 | 颜色不是买卖信号；缺失值不是零 |
| 历史走势 | 选择行业，查看官方行业 PE 或 PB 的历史变化 | 无效值处可能断线，不应脑补连续数据 |
| 涨跌排行 | 切换近 5 个交易日、月初至今、年初至今收益 | 来自官方指数收盘价的锚点收益，不是你的持仓收益 |
| PE-PB 象限 | 横轴为当前官方 PE，纵轴为当前官方 PB；颜色表示 PE 历史百分位 | 虚线是过滤后且 PE/PB 均为正值的行业集合中位数，不是合理估值线 |
| 数据明细 | 查看行业摘要，点击表头排序 | 先确认层级、日期和数据状态 |
| 行业成分 | 选择行业，搜索成员股票，查看当日估值与同业位置 | 个股同业百分位不是个股自身多年历史百分位 |
| SW2014 档案 | 查看截至 2021-12-10 的 SW2014 一级行业封存档案 | 不与 SW2021 拼成一条历史，也不参与当前层级排行 |

全局“行业搜索”用于按名称或指数代码过滤显示。成分页另有“成分股搜索”。搜索不重新定义百分位分母，也不会触发数据更新。

当前页面没有承诺一键导出 Excel 或 CSV 的按钮。需要表格原文件时，应由维护者从**已验证、明确 run_id 的快照**中按数据字典提取；不要自行编辑快照内部文件。

### 一个推荐的阅读顺序

1. 在总览选择 L1，确认日期，比较大行业的历史位置。
2. 切换 L2 或 L3，缩小到更细行业。
3. 在历史走势选择目标行业，分别查看 PE 和 PB。
4. 到行业成分页选择该行业，看成员状态、估值和有效样本覆盖率。
5. 回到数据明细核对具体数值，不只凭颜色下结论。

## 4. 两种“百分位”不能混为一谈

### 4.1 行业历史百分位

行业 PE/PB 取自 Tushare 的官方行业指数接口 `sw_daily`，不是把股票估值平均出来的。

它比较“某行业目标日的 PE/PB”与“这个行业截至目标日的有效历史观测”。只使用有限、严格大于零的值，包含目标日自身，至少需要 252 个有效观测。SW2021 从 2021-12-13 开始；部分二、三级行业的有效起点更晚，因此历史样本长度可能不同。

例如 PE 历史百分位为 20%，意思是约 20% 的有效历史观测小于或等于当前 PE；不表示未来上涨概率是 80%，也不表示价格低于合理价值 80%。

### 4.2 个股同业百分位

它比较“同一个目标日、同一所选层级行业内”的股票 PE_TTM 或 PB：

```text
百分位 = 小于或等于当前值的有效样本数 ÷ 有效样本总数 × 100
```

有效值同样要求有限且严格大于零，包含自身，至少需要 5 个有效样本。

例：5 个有效 PE_TTM 为 `5、10、10、20、30`。其中一个值为 10 的股票，百分位是 `3 ÷ 5 × 100 = 60%`，因为相等的两个 10 都计入“小于或等于”。这只是公式示例，不是实际股票数据。

页面同时披露成员数、有效样本数和覆盖率。覆盖率低时，不能把结果当作所有成员都参加了比较。成员纳入/调出边界或归属重叠无法确认时，受影响行业不计算同业百分位。

### 4.3 单位和空值

- 市值在页面显示为亿元人民币；底层供应商原始单位为万元，两者不要直接混比。
- `DV_TTM` 按供应商百分比原值显示，不需要再乘 100。
- 空值或“不可用”不是零，不自动意味着亏损、退市或软件故障。
- `ACTIVE` 表示成员关系按现有规则有效，不证明股票仍上市、可交易或未停牌。
- 行业未发布官方行情时仍可能有目录和成员，但行业估值不会用个股数据补造。

## 5. 怎样更新数据

### 5.1 更新到最近可更新交易日

确认你愿意联网并在**当前便携实例**写入新数据后，点击页面右上角 **“更新至最近开市日”**。

1. 页面显示作业阶段和进度。只提交一次，避免连续点击。
2. 更新过程中仍可浏览原快照；进度暂时不动不一定是失败。
3. 成功后出现“新数据已就绪”，但页面仍保持原来的快照。
4. 点击 **“切换到新快照”**，再检查顶部日期是否已经改变。

程序不会定时更新，也不会打开页面就自动拉取最新业务数据。真实更新耗时受数据量、账户权限、频次和网络影响，本手册不承诺固定时长。

### 5.2 为什么有时没有今天的数据

本项目按**北京时间 18:30**选择日更目标：

| 情况 | 选取哪一天 |
| --- | --- |
| 今天开市，尚未到 18:30 | 上一交易日 |
| 今天开市，已到或超过 18:30 | 今天 |
| 今天休市 | 交易日历声明的最近交易日 |

这是项目的目标日选择规则，不是 Tushare 保证在 18:30 数据一定齐全。目标确定后，缺数据、分类冲突或权限问题仍会失败，不会悄悄退到更早日期当作更新成功。

如果显示“已是最新”或 `ALREADY_UP_TO_DATE`，不会创建新快照或重新抓取行业、成员和个股业务数据，但仍会使用一次交易日历查询来确定目标日。因此它不等于完全没有联网。

### 5.3 查看指定历史日期

1. 在“历史开市日”选择日期，范围从 2021-12-13 开始，必须是官方开市日。
2. 点击 **“载入历史开市日”**。这不是单纯的日期筛选：该操作可能联网并创建历史快照，应作为一次明确的数据作业对待。
3. 等待成功，再按提示切换到该快照。
4. 要返回日更数据，点击 **“载入当前快照”**，这是读取当前定位，不会因为返回而创建新更新作业。

历史作业不改写日更 current。历史成员按目标日的生命周期规则判断，不是把今天的成员名单倒灌到过去。

### 5.4 更新失败怎么办

保留页面错误码、作业 ID、目标日期以及发生阶段。旧的已验证数据一般仍可继续浏览；若系统提示待恢复事务，先按第 8 节处理，不要通过编辑文件强行恢复页面。

“更新成功”需要看到作业成功、点击切换后新日期与内容可读。仅有 `SERVING`、Token 被读取、进度达到某个百分比，都不能替代这个确认。

## 6. 停止、再次启动和换端口

正常停止：先等更新或历史作业达到成功/失败终态，再回到服务终端按 **Ctrl+C**。只关闭 Chrome 页面不会停止后台服务。

下次继续使用：双击同一个启动文件。有效的 `data/state` 会继续使用，不会被初始 9 月 4 日数据覆盖。此前临时输入的 Token 若没有其他本机来源，需要重新输入。

若提示端口占用，先确认是否已经启动过同一个软件。不要为了释放端口杀掉全部 Python 进程。

必要时在终端进入**便携包根目录**，换用 8766：

```sh
./Start-Mac.command serve --port 8766
```

Windows 命令提示符进入对应包根目录后：

```bat
Start-Windows.cmd serve --port 8766
```

这时浏览器地址也要改为 `http://127.0.0.1:8766`。仍然只在本机监听。不要同时运行两个实例指向同一数据目录。

## 7. 数据保存、备份与换电脑

### 7.1 哪个目录保存我的更新

```text
便携包根目录/
  Start-Mac.command 或 Start-Windows.cmd   启动入口
  app/、runtime/、packages/                固定程序与运行环境，不编辑
  seed-data/                              固定初始数据，不编辑
  package-manifest.json                   静态文件校验清单，不编辑
  data/
    state/                               本实例的后续数据与作业状态
```

便携版不会把更新写进原作者电脑的系统数据目录。首次运行会在本实例创建并初始化 `data/state`；以后更新只使用这个实例的数据根。

### 7.2 同平台换电脑

1. 等作业结束，在原电脑停止服务。
2. 将**整个便携文件夹**完整复制到新电脑，不仅是启动文件或 `runs`。
3. 保留原电脑副本，直到新电脑启动、快照日期和内容核对通过。
4. 在新电脑启动并按需重新提供自己的 Token。

迁移后的目标仍必须符合平台架构与系统要求。复制时不要保持服务继续写入。

### 7.3 同版本跨平台迁移

1. 停止原实例，完整备份它的 `data` 文件夹。
2. 在目标电脑解压本版对应平台的新包，**先不要启动**。
3. 确认新包内尚无 `data`，再把旧实例的整个 `data` 放到新包根目录下，形成 `新包根/data/state`。
4. 启动后由程序校验。通过前保留旧副本。

不要复制旧平台的 `runtime` 覆盖新平台；不要覆盖已经使用过的新实例 `data`；不要将两个 `runs`、ledger 或 pointer 合并。

上述步骤是同版本迁移路径。Intel/Windows 对应真机仍需实际验证。**跨版本升级不是同一件事**：本版没有通用的自动数据迁移器，应先由维护者确认新旧源码与快照兼容性，不直接覆盖升级。

## 8. 常见问题与安全处理

| 现象或错误码 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| Mac 解压报错误 94 | 先核对接收文件的 SHA-256；不一致就保留旧副本并重传，完全一致后再查空间、目录权限和解压工具 | 不仅凭错误码断定压缩格式有问题，不先关闭系统防护 |
| Mac 提示未知开发者或未经公证 | 确认来源与校验值，按下方 Apple 说明处理具体项目；受管理电脑联系管理员 | 不关闭 Gatekeeper，不批量移除隔离标记 |
| `BUNDLED_PYTHON_UNAVAILABLE` | 核对包选对、完整解压、私有解释器和执行权限存在 | 不随意改成系统 Python 或另一个平台的 runtime |
| `PACKAGE_INVENTORY_MISMATCH` / `PACKAGE_HASH_MISMATCH` / `PACKAGE_FILE_CHANGED` | 保留 `data`，从可信 ZIP 解压到全新目录，核对静态文件与额外文件 | 不修改 `package-manifest.json` 来认可变动 |
| `SNAPSHOT_METADATA_UNEXPECTED` | 保留数据和错误码，交维护者核对；若仅未使用的初始副本出错，可重新解压到新目录 | 不在冻结快照里新增说明、截图或 Finder 元数据后改清单 |
| 浏览器无法连接 | 检查服务终端是否还在、端口是否正确、是否在同一台电脑访问 | 不将地址改成局域网 IP |
| 白底、按钮散乱或提示本地服务 | 关闭 `file://` 页面，启动服务后使用 HTTP 地址 | 不靠触发更新解决 CSS/JS 加载问题 |
| `PORT_UNAVAILABLE` / `CONCURRENT_UPDATE` | 确认是否已有自己的实例或作业，等其终态 | 不删除锁文件，不终止不明进程 |
| `TOKEN_TERMINAL_REQUIRED` | 使用本机真实终端正常启动，再按提示输入或回车 | 不把 Token 放到命令参数、网页或脚本中 |
| “未配置 token”或更新认证失败 | 区分没找到 Token、Token 无效、权限不足、频次或网络问题；按安全错误码核查 | 不把“找到 Token”当成接口调用已通过 |
| `ENDPOINT_ROW_LIMIT` / `MEMBER_ROW_LIMIT` | 将安全错误码交维护者核对数据完整性 | 不截断后发布，不忽略缺行 |

### 8.1 传输校验：避免重复遇到损坏副本

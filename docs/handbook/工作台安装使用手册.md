# 工作台安装使用手册

本手册适用于新统一工作台 `run_workbench.py`。旧 `run_dashboard.py`、`portable/Start-Mac.command` 及原手册描述的是兼容基线，不能用于启动新三页面。当前交付目标为 macOS 本机，服务仅监听 `127.0.0.1`。

## 1. 安装与首次启动

准备完整的新项目源码和本机 CPython 3.11–3.14，推荐使用验收环境同版本。进入项目根目录；以下第一条命令仅适用于不存在 `.venv` 的新目录。不要复制其他电脑的虚拟环境。

```bash
python3.14 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements-workbench.lock
.venv/bin/python -m pip check
.venv/bin/python -B run_workbench.py doctor
```

安装失败先处理错误，不降级锁文件、不忽略哈希、不继续启动。完整锁包含旧基础依赖及 Excel、中文排序扩展；`pip install -e .` 不替代锁文件安装。页面无远程 CDN、Node 或 npm 运行依赖。

`doctor` 不写数据、不创建锁、不联网。`dependencies_locked=true` 表示安装版本符合锁；`token_configured=true` 仅表示能读取非空凭据；`formal_source_eligible=true` 表示当前有 Git 提交且无未提交改动。这些状态都不能单独证明账户有全部接口权限。缺少旧 SW2014 档案不阻止新批次。

```bash
.venv/bin/python -B run_workbench.py serve
```

终端出现 `SERVING` 后，在 Chrome 打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。保持终端运行；它不会自动打开或切换浏览器。双击根目录 `start_macos.command` 等价于该入口，缺少环境时只提示安装命令。

默认新数据根：`~/Library/Application Support/ashare-industry`。原 `~/Library/Application Support/swivd` 不会修改。自定义目录时，每次命令都传同一个 `--data-dir`。不要把旧实例直接当成新数据根；使用第 6 节导入。

## 2. Token 与取数权限

应用只读取进程环境变量 `TUSHARE_TOKEN` 或既有 Tushare 本机配置，使用官方 HTTPS 接口。真实凭据不放在网页、代码、命令行参数、截图或日志里。请沿用本机安全的凭据管理方式，在启动该进程前配置环境；应用没有 `.env` 自动加载器或网页 Token 表单。

首次统一更新需要股票生命周期、交易日历、行情、个股估值、个股资金流、四分类及成员接口的实际权限。错误会安全显示接口类别/原因，不回显凭据。`doctor` 不消耗账户请求，真实权限只能通过已授权取数验证。资金流与估值更新共用同一批次，不会独立发布两页。

正式数据任务要求 clean committed 源码。当前施工工作树如有未提交改动，会阻止正式更新但允许浏览；代码审阅后是否提交由用户决定。开发证据使用独立目录并明确加标记：

```bash
.venv/bin/python -B run_workbench.py serve --development --data-dir .local/evidence/dev-instance --no-scheduler
```

开发模式只能写 `.local/evidence` 或系统临时目录，关闭自动调度，不会变成正式快照。该命令仅启动页面；手动更新仍会真实联网，需符合当前会话授权。

## 3. 更新、回补与停止

默认应用存活时启动内置调度：北京时间 19:30 尝试日更，19:45、20:15 对可重试失败重试。启动或休眠唤醒会检查错过任务。19:30 前候选日为此前最近交易日；周末休市不会伪造当日行情。应用退出即停止，不安装系统后台任务。

首次更新先建立最近可用交易日，再由后台分批推进近五年历史。同花顺没有已采集的同日成员证据时历史留空；其他分类也受实际接口起点、权限、边界与覆盖限制。日更优先于历史回补，每个完整交易日结束后可以让位。

页面“更新数据”和 CLI 共用作业与写锁。CLI 同步执行后打印作业结果：

```bash
.venv/bin/python -B run_workbench.py update
.venv/bin/python -B run_workbench.py backfill --start-date 20260901 --end-date 20260916
```

日期是 `YYYYMMDD`，不可超过当天；上面仅为格式例子，执行前替换为所需的已批准范围。手动回补按完整交易日分批持续推进范围；停止后用相同命令恢复，可复用已完成检查点。仅需有界验证时加 `--max-days 1`（允许 1–40）。不要为加速另启多个写任务。

早于最新目标日的历史日期，仅在底表独立股票集合不完整（受控错误 `INDEPENDENT_UNIVERSE_INCOMPLETE`）且失败证据闭合时，应用保留原因后继续其他日期。网络、权限、schema、哈希等错误，以及最新日失败，仍会暂停作业。相同相关代码与证据版本下，默认跳过已隔离的失败日期，后台调度也不会反复请求它们；这表示当前证据未通过，不表示永久不可恢复。页面“历史补齐”可查看失败日期及原因，勾选“重试已失败日期”后才会明确重试；每次打开该对话框默认不勾选。CLI 对应参数如下，同一作业内每个失败日最多重试一次：

```bash
.venv/bin/python -B run_workbench.py backfill --start-date 20260901 --end-date 20260916 --retry-failed
```

`remaining_days` 包括失败日期和待尝试日期，`remaining_attemptable_days` 只计当前还能继续尝试的日期。`attempted_days` 是已尝试日期列表，包含本次失败日。进度条代表可尝试交易日的扫描进度；`scan_complete=true` 不等于历史完整。范围已扫描完但仍有失败日时，作业以 `FAILED / HISTORY_INCOMPLETE` 结束，CLI 返回非零状态，并保留已成功日期和失败明细。有界执行显示 `CHUNK_COMPLETE` 或 `CHUNK_COMPLETE_WITH_GAPS` 时仍需查看剩余量，不能当作全范围成功。相关数据或代码证据改变后可重新判定可尝试状态；也可在排查原因后明确选择重试。`history_complete=true` 仅表示所选范围的交易日分片都已入库，各行业指标仍可能因真实历史归属缺失而为空。

历史回补运行时仍可点击“更新数据”提交日更，后端会在完整交易日边界先处理日更，再继续回补；已有日更运行或排队时按钮禁用，避免重复提交。历史补齐按钮在已有作业时禁用。

只浏览已有结果、断网展示或排障时关闭自动调度：

```bash
.venv/bin/python -B run_workbench.py serve --no-scheduler
```

这不会禁用用户明确点击的手动任务。查看已有结果无需 Token。停止前等待当前作业结束，在终端按 `Ctrl+C`。强制退出可能保留检查点或待恢复事务，下次启动只恢复新工作台自己的事务；不手工删除锁、pointer、ledger 绕过校验。

## 4. 页面阅读与导出

三个主页面保留体系、层级、周期和搜索条件。申万/中信有 L1/L2/L3；通达信 880、881 为独立系列；同花顺为行业集合，可以多归属，不跨集合相加。点击行业名称进入成分、资金贡献与历史详情。

申万/中信二级可按一级父行业筛选，三级可按二级筛选；通达信与同花顺不建立虚构父层级。资金页打开行业默认按净流入降序看成员贡献，期间成分页默认按股票代码排序。估值历史走势图可选择适用估值指标或官方指数收盘点位。数据质量折叠区按当前体系/层级逐日列出已归属与未知归属资金，以及未知股票代码；父行业和搜索不改变这里的全层级核对范围。

日是交易日；周为周一至周日；月为公历自然月。估值取周期要求的期末交易日，资金按每日当时归属累计。正在形成的周期和缺交易日会单独标识；缺失不是零。正值样本不足五只会提示小样本，历史分位不足 252 个有效交易日留空。分位是统计位置，不是买卖建议。

“已确认成员”仅计截至期末有证据的成员，历史缺口下的 0 不代表行业实际没有股票。“期末应有记录”和“期末已取记录”也只对应期末已确认成员的资金记录，不是整周或整月的日×股记录总数。悬停相应表头或数值可查看说明。

官方 PE/PB 与自建成分中位数口径分开。申万、通达信可在接口支持时展示官方值；同花顺/中信以自建中位数为主。资金不按 PE/PB 正值条件剔除成员。

列表表头循环切换默认、升序、降序，缺失始终在末尾；数值按未四舍五入的原值比较。每个页面固定一个 `batch_id`。后台完成新批次只出现提示，点击“切换新批次”后三页和详情一起更换，避免阅读过程中混接。

- **当前视图 CSV**：当前批次、页面/视图、分类层级、周期、搜索和排序，带口径与批次列。
- **四分类 Excel**：同一批次/周期的四分类全部层级，另含口径和审计，共六个工作表；不受当前分类、搜索或排序限制。保留官方与自建估值独立列。

导出在页面显示独立作业，完成后点击下载。没有真实数据时不会提供默认模拟行情。

## 5. 验证、备份与迁移

```bash
.venv/bin/python -B run_workbench.py verify
.venv/bin/python -B run_workbench.py verify --batch-id BATCH-YYYYMMDDTHHMMSS-xxxxxxxxxxxx
```

第二行必须替换为已有批次 ID。验证读取 manifest 回执、递归对象引用与冻结源码内容，不联网、不重算研究结论、不晋级结果。`EMPTY` 表示没有已发布批次，不能当作数据验收通过。

备份前停止服务及所有 CLI 作业。复制**整个新数据目录**，包括 `current.json`、`batches/`、`objects/`、`run_ledger.ndjson`、检查点、调度状态及已导入的 `legacy/`。仅复制一个 CSV、manifest 或 current 指针无法恢复完整数据。

新电脑重新创建本地 `.venv` 并按锁安装依赖，再将完整数据备份复制到独立的新数据目录；先使用 `verify --data-dir <新目录>`，验证通过后 `serve --no-scheduler --data-dir <新目录>` 回读三页，再决定启用联网更新。Token 单独安全配置。源码与数据备份是两个对象，不能用虚拟环境或便携模板代替源码。

## 6. 可选旧档案导入

`/legacy/` 使用同一个服务，保留原估值页面和 SW2014 封存视图，仅允许读。未导入显示未安装，不影响新数据。支持完整旧数据根的已验证 current 快照，或明确的完整 `UPDATE_LATEST` 快照目录；不是某个零散 CSV 或原项目源码目录。

```bash
.venv/bin/python -B run_workbench.py import-legacy --source "/完整旧快照或旧数据根"
```

导入先执行原快照完整校验，复制其 manifest 声明的文件、manifest 和原始 `SHA256SUMS`；这份校验清单保留原字节，不重新生成。新目录先暂存、再校验、最后原子更名为新数据根内的 `legacy/`。大快照校验和落盘可能需要数分钟，期间保持终端运行。来源不动，已有导入不自动覆盖。失败的暂存目录会清理，写锁文件可能保留。导入完成后访问 [旧档案页面](http://127.0.0.1:8765/legacy/)。旧档案的声明依赖缺失或哈希损坏会失败关闭，不删除原校验来“兼容”。

## 7. 常见故障

| 现象 | 处理 |
|---|---|
| 依赖缺失或不匹配 | 用完整锁安装并执行 `pip check`；不要隐式升级 |
| 正式更新提示源码未提交 | 先审阅代码；本次未授权自动提交。已有数据仍可读 |
| 无数据或首次历史分位为空 | 查看当前作业、覆盖日期及原因；空值可能是样本或历史证据不足 |
| 端口被占用 | 不关闭不明进程；用 `serve --port 8766` 并访问对应 127.0.0.1 地址 |
| 网络/权限/全市场记录缺口 | 旧批次保留；检查明确原因后重试，不用旧日数据冒充成功 |
| 同时更新失败 | 等待唯一写任务结束；不删锁文件或另开进程绕过 |
| 更新响应丢失 | 先查看活动任务，避免重复提交；页面会先读取已有作业 |
| 哈希或发布恢复失败 | 保留原始数据目录取证，从完整备份恢复到另一个目录验证 |
| 旧档案导入失败 | 补齐原快照声明的源档案，或保持未导入；新功能不受缺件影响 |

实施验收结果见 [实施状态](../IMPLEMENTATION_STATUS.md)。新离线测试、旧核心测试、旧便携测试和真实 macOS/Tushare 验收分别记账；部分通过不能称全量通过。工作台仅供本地研究，没有可交付的新回测结论。

|---|---|

| 合为一个项目，一次启动 | 一个 Python 本地服务，估值、资金流、融合三个页面；独立 `.venv` 与完整哈希依赖锁 |

## 后端职责边界

纯领域层负责身份、时点、估值和周期；provider 只取数与规范化；store 只负责不可变对象和可恢复发布；query 只读取固定批次；jobs/scheduler 编排单写者和优先级；HTTP/CLI 不写财务公式；前端只格式化、排序、筛选和绘图。

历史失败记录独立于成功数据。仅受控的历史底表独立集合不完整可以留证后跳过；网络、权限、schema、哈希等错误仍停止任务。重试索引、记录链、原始响应和捕获源码要闭合，缺日不会伪装成零或成功。页面轮询读记录级状态，写任务核验完整证据，避免每次刷新解压大量历史原始数据。

当前保留一项P2性能限制：若已导入完整旧档案，服务进程首次打开同步做严格旧档案校验，本次约51秒；后续已有缓存。后继优化可在旧档案独立入口执行严格校验，避免新三页首读等待，本次未改动冻结实现。

详细职责、输入输出和恢复约束见 [接口契约](implementation/INTERFACES.md) 与 [工程迁移对照](implementation/IMPLEMENTATION_MAP.md)。

## 本次对抗审查修复

- 用真实成员变动反例核对周/月资金，确认逐日归属累计，防止拿期末篮子回算整月。
- 历史单日失败不再阻断其他可尝试日期；同一证据版本不自动重复请求坏日，明确人工重试每作业每日期一次。
- 失败索引必须与记录链及已发布引用对账，删除、遗漏、回退不能静默清空失败状态。
- Chrome 实测发现零收益/零金额触发空 CSS class、整表无法显示；已修复并实际重测。
- 历史状态损坏显示“未知”，保留已发布数据阅读，阻止依赖该状态的回填。
- 日频资金记录数与周/月交易日数分别命名；缺日不伪造记录数量。
- 盘前或休市首次回填时，声明历史范围包含强制采集的最近有效交易日；发布前拒绝倒置范围。
- 成功作业隐藏过期阶段计数；同日更新明确显示“已是最新”及数据日期，实际 Chrome 复验通过。

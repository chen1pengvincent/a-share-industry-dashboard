# 工程交接与迁移对照

本实现对应 [已批准方案](APPROVED_PLAN.md)、[数据和接口契约](INTERFACES.md)、[机器规格](../../PROJECT_INTEGRATION_SPEC.json)。当前验证与剩余门槛以 [实施状态](../IMPLEMENTATION_STATUS.md) 为准；使用方法见 [安装使用手册](../handbook/工作台安装使用手册.md)。

## 从需求到代码

| 用户目标 | 实现入口 | 核心约束 |
|---|---|---|
| 共用一个Tushare源 | `transport.py`、`provider.py`、`jobs.Pipeline` | 一个客户端、一套原始响应；同参数同作用域复用；申万两轮独立成员检查不被去重 |
| 一个项目启动三页 | `run_workbench.py`、`start_macos.command`、`server.py`、`web` | 一个本地服务和一个明确current批次；网页GET不联网 |
| 日/周/月融合 | `metrics.py`、`periods.py`、`query.py` | 行业估值取期末应有交易日；资金逐日按当时归属相加；缺日保留NA |
| 四种行业体系 | `taxonomy.py`、`provider.py` | SW2021和CI三级；THS实际行业板块、允许重叠；TDX880/881分开 |
| 全部表头三态 | `sorting.py`、`web/app.js`、`web/legacy/app.js` | 默认→升序→降序→默认，空值始终最后，原值精度、拼音和稳定ID |
| 真实数据可靠性 | `validation.py`、独立测试与`scripts/verify_*` | 独立有理数重算；行业/成员/市场诊断可对账；失败不切换current |
| 本地自动更新 | `scheduler.py`、`jobs.JobManager` | 19:30/19:45/20:15，单写者，日更优先，历史按日检查点恢复 |
| 导出与迁移 | `exports.py`、`cli.py`、`legacy.py` | CSV等于当前视图；Excel六Sheet；备份引用闭包、旧档案严格校验 |

## 旧功能与规则迁移

| 原功能或口径 | 新工作台行为 | 原实现处理 |
|---|---|---|
| 申万官方PE/PB及历史百分位 | 估值页继续单独提供官方口径，并增加成分中位数口径 | `src/swivd`核心、身份和验证器不改 |
| 估值六类分析视图 | 总览、估值热力图、历史走势、涨跌排行、PE–PB象限、数据明细；支持四分类 | 新网页实现；旧快照页在`web/legacy`只读提供 |
| SW2014旧档案 | 可选导入，成功校验后只读浏览；不与SW2021拼成连续序列 | 完整复制原manifest、SHA256SUMS及其引用文件，不重生成旧校验 |
| 估值行业成员规则 | 股票生命周期、日期有效成员、归属边界未知、同层身份约束用于资金聚合 | 新纯领域层调用必要的旧受控身份规则 |
| 资金净流入 | 统一取个股`moneyflow.net_mf_amount`；内部为0.01万元整数、显示亿元 | 不改为大单推算，不排除亏损股票 |
| 资金项目允许的小比例漏归属 | 不宣称完整行业金额；未知归属单独展示，已确认部分可对账 | 原项目未改，新契约采用已批准严格口径 |
| THS板块行情 | 官方close可读；PE/PB没有对应来源时留空 | 不把行情里的买卖量当统一资金指标 |
| TDX两种行业系列 | 880、881分别选择和诊断 | 不推断父子关系，不跨系列合计守恒 |
| 历史成员缺失 | THS必须有当天采集证据；结构性缺失只影响相关指标 | 不拿当前成员回填过去 |
| 周/月估值、资金 | 估值为期末值；资金为自然周期累计，日级未知小计仍能累计 | 不是滚动5/20日，也不是期间估值平均值 |

新增百分位只使用截至观察日、相同成员证据口径的有效日序列；至少252个有效日。PE和PB各自筛选正数有限样本，不取共同交集。有效成分不足5只仍显示中位数并标注小样本；同业百分位不足5只时留空。

## 存储与恢复

源码和数据分别管理。正式数据根默认是`~/Library/Application Support/ashare-industry`；开发验收仅在`.local/evidence`或临时目录。

1. `objects/`保存gzip压缩、内容寻址的原始响应、日输入、日结果、查询视图、源代码快照；引用含SHA-256、解压字节数和对象类型。
2. `batches/`保存不可变manifest及校验文件；所有页面、导出和历史明细绑定同一个batch_id。
3. `current.json`是带哈希和scope的定位器；仅已在`run_ledger.ndjson`提交的批次可查询为发布批次。
4. 写锁覆盖数据作业和发布。发布事务记录PREPARED/COMMITTED；重启验证对象后恢复旧完整批次或新完整批次，不暴露半批数据。
5. `checkpoints/`复用同源码的完整每日分片。源码变化时从冻结输入重算，并保留原取数源码血缘；不能把旧结果改名为新源码结果。
6. `jobs/`保存作业状态；历史回补分段让出执行机会给日更。退出留下明确中断状态，重试复用已完成日。
7. `history/`保存历史失败/恢复索引，不可变记录保存在objects；记录链与已有发布引用共同核对，缺失或回退须报错。仅明确的历史底表独立集合不完整可按日留证，继续后续日期；网络、权限等异常仍暂停。失败日不会进入成功分片。

迁移必须复制整个数据根（含objects、batches、current、ledger和可选legacy），运行`verify`后再离线启动。不要仅复制current或单张CSV。程序不提供手工改pointer的“修复”捷径；损坏证据保留，按明确批次检查和修复。

## 安装与后续施工顺序

1. 使用项目独立虚拟环境和`requirements-workbench.lock`完整哈希锁安装；运行doctor和pip check。
2. 按登记入口运行新工作台测试、UI行为测试及指定旧身份/SW2014回归；网络底表验收、实际Chrome验收单独记录，不能用mock替代。
3. 审阅所有新源码diff及验收报告。源码当前存在未提交的实现变更，正式更新门槛会阻止运行。
4. 取得针对新项目本地提交的明确批准后，提交已审阅源码、测试、契约和文档；开发真实数据、凭据、`.venv`及`.local`保持排除。此步骤不等于push或发布授权。
5. 在干净提交树上完成正式首次更新，再由应用内调度持续回补近五年；五年是目标范围，外部无法恢复的历史仍明确为空。
6. 每次后续改动按受影响边界选择验证；改动provider要跑真实接口/边界证据，改动财务定义要独立数值复核，改动UI要实际Chrome检查。

全量历史可能持续较久。TDX成员接口按日期和板块查询、单次上限3000；本实现按当日目录逐板块取证，不能为加速而复用今天的成员。实际耗时以作业进度为准，首次最新日与历史回补分别展示。[Tushare TDX成员接口](https://tushare.pro/document/2?doc_id=377)

## 权限边界

本工作台是本地数据研究和展示工具。实施批准覆盖新项目、本地开发证据和约定的本地运行；原两个项目及其运行实例保持独立。当前没有commit/push/Release、系统自动化安装、投资策略、回测晋级或交易授权。遇到失败保留当前成功批次与失败记录，不删除证据来“恢复成功”。

新源码目录的 Git origin 目前仍用于定位原估值来源仓库。集成项目尚无单独发布仓库；本地提交批准不包含向该来源仓库推送，新发布目标需要另行明确。

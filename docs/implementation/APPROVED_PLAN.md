# A 股行业估值与资金流工作台施工方案

版本：2026-09-16  
交付范围：合并方案、数据口径、实现路径和验收标准。本轮已完成源码核查、三轮需求确认和独立对抗审查，尚未实施或调用真实账户取数。

## 一、目标与施工基线

### 1.1 最终交付

建设一个在 macOS 本机运行的项目，一次启动后，通过同一个网址访问三个页面：

| 页面 | 交付内容 |
|---|---|
| 行业估值 | 保留现有申万估值功能，扩展四套行业分类及成分股估值统计 |
| 行业资金流 | 新建网页，承接现有资金流计算与 Excel/CSV 导出能力 |
| 估值与资金流融合 | 在同一行业、同一观察周期下，同时查看估值水平、估值历史位置和资金净流入 |

三个页面共用 Tushare 客户端、行业身份与成员数据、更新作业、历史存储和发布批次。

已确认的产品决定：

- 四套分类均覆盖三个页面：申万、同花顺、通达信、中信。
- 日为交易日，周为周一至周日，月为公历自然月。
- 周、月展示期末交易日估值与期间累计资金净流入。
- 四套分类统一新增成分股有效 `PE_TTM`、`PB` 中位数；申万、通达信官方估值另行保留。
- 历史按当时有依据的行业归属计算，无法证实的部分留空。
- 首次初始化回补近五年的可验证历史。
- 应用运行时自动更新，默认北京时间 19:30；保留手动更新。
- 仅验收 macOS 本机版本。
- 所有数据列表支持“默认 → 升序 → 降序 → 默认”。

## 二、产品行为与统一数据口径

### 2.1 页面与操作

统一顶部导航提供“行业估值 / 行业资金流 / 融合分析”，共用以下选择条件：

- 行业体系。
- 该体系真实提供的层级或代码系列。
- 交易日、自然周、自然月及具体日期。
- 行业搜索、父行业筛选。
- 当前数据截止日、更新状态、缺口说明。

页面切换保留行业与周期条件；页面自己的表格排序分别保存。

| 页面 | 核心展示 | 默认行为 |
|---|---|---|
| 行业估值 | 原总览、热力图、历史走势、涨跌排行、PE-PB 象限、明细、成分股及旧档案入口 | 申万保持官方估值入口；其他体系提供适用的官方值和自建统计 |
| 行业资金流 | 行业净流入排名、历史趋势、成分股贡献、覆盖与异常明细 | 同体系、同层级内按净流入降序 |
| 融合分析 | 行业比较表、估值位置与资金流散点图、行业历史联动详情 | 默认申万一级、最新交易日、自建成分估值统计 |

融合主表至少包含：

> 行业名称、代码、层级/系列、PE_TTM 中位数、PE 历史百分位、PB 中位数、PB 历史百分位、期间资金净流入、资金排名、估值有效样本数、资金覆盖情况、数据状态。

官方估值通过独立字段或明确的口径切换查看，列名必须包含“官方”或“成分中位数”。不得在同一列中根据数据是否缺失，自动混用两种来源。

融合散点图默认使用“成分 PB 历史百分位 × 期间资金净流入”，可切换 PE。缺任一坐标的行业保留在表格中，并说明未进入图表的原因。图表不生成买卖信号或综合评分。

点击行业进入详情，显示期间资金贡献、期末成员估值和行业变更记录。期间贡献涉及已退出成员时仍保留其实际贡献，不只展示期末成员。

### 2.2 行业身份与分类规则

行业连接使用稳定业务标识：

```text
taxonomy + taxonomy_version + level_or_series + industry_code
```

目录代码、行情代码、成员接口代码分别保存；中文名称仅用于展示和搜索。

| 体系 | 页面结构 | 成员与汇总规则 |
|---|---|---|
| 申万 SW2021 | 一级、二级、三级 | 继承估值项目身份校验、父子关系和成员边界规则；保留特钢受控别名验证 |
| 同花顺 THS | 真实行业板块列表 | 保留实际多重归属，不虚构三级结构；一只股票可计入多个真实行业 |
| 通达信 TDX | 880、881 系列分别展示 | 系列内独立分析，不把两个系列命名为一级、二级 |
| 中信 CI | 一级、二级、三级 | 按一级行业拆取并继续处理触限分区；新增历史成员恢复 |

具体约束：

- 保留申万合法但不发布指数的行业。其资金流、自建估值可以存在，官方估值显示不可用。
- 同花顺沿用现项目对主行业目录的认证方法；资金金额仍来自统一个股资金流。
- 行业数量属于版本核验依据。遇到新增、撤销、代码复用、父路径变化时，记录差异并验证，不能靠补名称或强行套用旧数量继续计算。
- 日常成员变化不创建新的估值统计口径；行业身份含义或分类版本发生变化时，才分开历史序列。
- 同花顺全表、通达信跨系列、申万或中信跨层级均不能直接相加作为全市场总额。
- 全市场总额独立从去重后的股票底表计算。

### 2.3 估值计算

**自建统计的市场范围固定为沪深 A 股**，与资金流覆盖市场保持一致；包括当日已上市、未退市的行业成员，不额外增加 ST 剔除或新股天数过滤。官方指数估值保持供应商原范围，并披露可能存在的范围差异。

数据来自 Tushare `daily_basic`，其中 `pe_ttm` 与 `pb` 分别计算。[每日指标文档](https://tushare.pro/document/2?doc_id=32)

计算规则：

1. 确认目标日成员集合及归属证据。
2. PE_TTM、PB 分别保留有限且大于零的值。
3. 分别取中位数；偶数样本取中间两项的算术平均。
4. 不做额外截尾、缩尾、市值加权或缺失填充。
5. 有效样本为零时显示缺失；1–4 个样本显示真实中位数并标“小样本”。
6. 分别披露成员数、取得个股记录数、PE 有效数、PB 有效数。
7. 个股记录存在但 PE 为空，与整条个股记录未取得，使用不同原因。
8. 停牌股若有当日合法估值记录，可以参与估值统计。

中位数表达的是“行业内有效样本的典型股票估值”，不称作官方行业指数估值。

官方估值来源：

- 申万：沿用 `sw_daily` 的 PE/PB。
- 通达信：使用 `tdx_daily` 的 PE/PB，严格解析字符串字段。
- 同花顺、中信：官方行情接口未提供 PE/PB，官方字段显示“不提供”，由已确认的自建统计满足估值观察需求。[通达信行情](https://tushare.pro/document/2?doc_id=378)、[同花顺行情](https://tushare.pro/document/2?doc_id=260)、[中信行情](https://tushare.pro/document/2?doc_id=308)

官方 PE 不擅自更名为 PE_TTM，也不承诺申万与通达信官方计算方法完全相同。

### 2.4 估值历史百分位

沿用现有项目的日度经验分布定义：

```text
历史百分位(t)
= 截至 t 的有效历史观测中“小于或等于当日值”的数量
  ÷ 有效历史观测数量 × 100
```

- 包含当日，不使用未来数据。
- 至少有 252 个有效日度观测才显示百分位。
- 按行业身份、指标、计算版本、市场范围和成员证据类型分别形成序列。
- 官方估值与自建中位数分别计算，不能拼接。
- 周、月页展示期末交易日对应的日度历史百分位。
- 缺失不计入样本，不填零、不向前填充。
- 显示样本起止日期、有效天数、缺失天数和并列情况。
- 原个股“同业百分位”继续保留其至少 5 个有效样本的规则，与行业历史百分位、中位数分别命名。

首次回补以初始化目标日向前五个公历年为起点，随后持续追加数据。新增统计采用该有效历史起点至观察日的扩展窗口，并明确展示窗口；旧申万官方序列继续遵守原分类版本起点，SW2014 与 SW2021 永不拼接。

### 2.5 资金流计算

统一使用 `moneyflow.net_mf_amount`，不以其他接口的“主力净额”替代，也不根据大小单买卖差重造该值。[个股资金流文档](https://tushare.pro/document/2?doc_id=170)

```text
行业日净流入
= 当日归属该行业的合格沪深 A 股 net_mf_amount 之和

行业期间净流入
= 期间各交易日行业日净流入之和
```

- 内部沿用 `0.01 万元` 整数精度；展示亿元时正确换算。
- 亏损、PE 为空或 PB 非正的股票，仍正常参与资金流计算。
- 只有已证实全天无交易的股票可豁免资金记录；部分停牌不能豁免。
- 北交所属于资金接口不覆盖，不能按零处理。
- 同额使用竞争排名，排序按未格式化数值进行。
- 无成员、成员不明、资金缺行与真实净额为零分别处理。
- 未知归属保留诊断股票清单和金额，不伪造为官方行业，也不参与正式行业排名。

### 2.6 日、周、月与历史成员

| 情况 | 固定处理 |
|---|---|
| 交易日 | 当日估值、当日净流入 |
| 已结束自然周/月 | 最后一个应有交易日估值、全部应有交易日资金合计 |
| 本周/本月尚未结束 | 截至当前数据日的期末估值与累计流量，标“进行中” |
| 月末休市 | 使用该月最后一个交易日 |
| 周期中缺少一个应有交易日资金值 | 完整期间资金值为空；详情可显示已知小计、覆盖天数和缺失日期 |
| 期末估值缺失 | 显示缺失，不退回之前有值的日期 |
| 整个周期无交易日 | 显示“本周期无交易日” |

先按每一天的成员归属计算，再汇总周、月。禁止拿期末成员对整个期间一次聚合。

历史成员证据分为：

- **官方带日期记录**：SW/CI 的成员生命周期、TDX 的目标日成员；仍须验证覆盖与日期语义。
- **当日采集归属**：THS 在目标交易日当天实际留存的完整成员响应。
- **未知**：无法证明对应日期的归属。

THS 的接口只提供最新成员，不能据此恢复首次采集以前的真实历史。[同花顺成员文档](https://tushare.pro/document/2?doc_id=261)

因此：

- THS 当日采集结果必须标明采集时间，不能称作官方历史点时记录。
- 隔天补跑不能补造前一天成员，遗漏的交易日保留空缺。
- THS 上线初期可能没有完整周月资金累计，历史百分位也需积累有效观测。
- 其他体系能回补到哪里，以真实数据证据为准；五年是目标范围，不承诺四体系五年全部有值。
- 历史重建注明“依据本次取得的历史记录”，不冒充当年实际留存的原始版本。

### 2.7 更新失败与指标缺失

将整批发布与单项指标可用性分开：

| 问题 | 处理 |
|---|---|
| 网络取数失败、权限不足、未解决的截断、日期错误、主键冲突、行情/资金底表完整性失败、哈希验证失败 | 整批不发布，保留上一有效批次 |
| 官方不提供估值、历史成员无证据、成员边界不明、有效估值样本不足、历史周期有缺口 | 相关指标为空，可发布带明确缺口的批次 |

继承估值项目对纳入日、退出日和重叠成员的谨慎处理：

- 能确定受影响候选行业时，只使相关行业指标不可用。
- 无法界定影响范围时，该体系相应日期的行业完整指标不可用。
- 已确认部分金额仅放在诊断信息中。
- 不以“已知行业金额＋未知桶守恒”证明各行业都完整。
- 原 CI 的 99.9%／10 只容忍规则保留在旧结果解释中；新融合指标不能用该阈值把未知归属认定为完整。

页面同时显示“本次更新结果”和“当前数据日期”，避免更新失败后仍给用户最新的错觉。

## 三、实现架构、接口与迁移

### 3.1 技术选择

沿用 Python 单服务与原生前端，不更换框架。继续监听：

```text
127.0.0.1:8765
```

采用以下调用关系：

```text
自动调度 / 手动更新 / 历史回补
               ↓
       统一作业队列与单写者锁
               ↓
         统一 Tushare 客户端
               ↓
      原始响应、行业身份、每日成员
               ↓
      估值计算 / 资金流计算 / 周月汇总
               ↓
       独立重算、完整性与哈希验证
               ↓
          原子发布统一批次
               ↓
       估值页 / 资金流页 / 融合页
```

资金流旧入口中自动执行测试、寻找 Codex 依赖路径等行为，不进入日更链路。抽取其中纯计算与导出能力，由新项目自身锁定和安装依赖。

在本机施工时使用独立目录：

```text
源码：/Users/chenyipeng/Desktop/Codex/Stock/a_share_industry_dashboard
数据：/Users/chenyipeng/Library/Application Support/ashare-industry
```

实施前完成新目录登记和对应规则记录。现有两个实例作为迁移来源，不原地覆盖。

### 3.2 共用数据获取

“获取一次”定义为**一个统一更新批次中，共用相同请求和原始结果**，不要求物理上每个接口只能请求一次。

实现要求：

- 共用一个凭据解析器、HTTPS 客户端、限流器、重试策略和请求审计。
- 同接口、规范化参数、字段和业务日期的请求，在同一批次内合并。
- 保留身份验证所需的两轮成员请求；验证轮次明确记录，不被普通缓存吞掉。
- 原始响应保存参数、采集时间、来源、记录数和哈希，不保存 Token。
- 处理各接口上限；恰好达到上限时继续拆分或证明完整，不能直接视为成功。
- 请求失败不能调用其他供应商补齐。
- 浏览、排序、筛选和读取导出文件不触发行情取数。

统一接口范围包括公共交易日历、股票生命周期、日行情、停复牌、每日指标、个股资金流，以及四套分类各自的目录、成员和行情接口。`moneyflow_ind_ths` 仅用于现有主行业目录认证，不替代统一资金金额。

### 3.3 存储与发布

采用**按日分片、不可变文件、内容哈希引用、预计算查询产物**。本版不引入数据库。

存储分为：

1. 原始响应与规范化日数据。
2. 行业目录和成员证据。
3. 行业日指标、周月指标、历史序列与成分详情。
4. 批次 manifest、查询索引、作业记录及唯一 current pointer。

关键规则：

- 原始日分片只保存一次，多个发布批次引用同一份文件。
- 不继续在每次日更中复制全部祖先历史。
- 每个可见批次封闭引用其数据、规则版本和三页查询产物。
- 浏览器始终绑定同一个 `batch_id`，页面切换不能分别取各自 latest。
- 后台成功后提示“新数据已就绪”；点击后统一切换整个应用批次。
- 回补历史可以发布新的查询版本，但最新业务日期不得倒退。
- 修订已有日期时创建 successor 分片与批次，保留旧字节。
- 回补或修订后，重算受影响周月及之后受影响的历史百分位。
- 查询产物按体系、层级、期间定位；历史和成分详情懒加载。
- 导出迁移包时包含完整引用闭包，不依赖原电脑绝对路径。

继续复用现有单写者锁与可恢复发布事务：提交前中断保留旧批次，提交后中断恢复新批次并补齐唯一成功记录。

### 3.4 最小公共接口

保留旧估值只读 API，新增统一 API；旧快照不原地升级。

| 接口 | 用途 |
|---|---|
| `GET /api/v2/current` | 返回已验证 current 批次、数据截止日与更新状态 |
| `GET /api/v2/batches/{batch}/catalog` | 分类、层级、日期范围及功能可用性 |
| `GET /api/v2/batches/{batch}/industries` | 按体系、层级、周期取得三页共同使用的行业指标 |
| `GET /api/v2/batches/{batch}/industries/{uid}/history` | 行业历史序列 |
| `GET /api/v2/batches/{batch}/industries/{uid}/members` | 期末成员估值与期间贡献 |
| `GET /api/v2/jobs/{job_id}` | 更新、回补和导出进度 |
| `POST /api/v2/jobs/update` | 提交统一更新 |
| `POST /api/v2/jobs/backfill` | 提交限定起止日期的历史回补 |
| `POST /api/v2/jobs/export` | 从指定批次生成导出，不联网取数 |

行业查询参数固定包含：

```text
taxonomy、level_or_series、period_kind、period_key
```

指标响应至少包含：

```text
value、status、reason_codes、metric_date、
expected_count、received_count、valid_count、
membership_evidence_kind、source_refs
```

另记录周期起止日、实际截至日、应有交易日数及有效交易日数。金额使用精确整数单位传递，前端排序不能先转成四舍五入的展示文本。

命令行保留统一入口，提供 `serve`、`update`、`backfill`、`doctor`、`verify` 和显式旧档案导入能力，全部使用同一数据根及作业锁。

### 3.5 自动更新与初始化

自动更新使用应用内调度，不安装系统后台任务。

- 北京时间 19:30 尝试更新当天交易日。
- 暂时性失败允许在 19:45、20:15 再尝试；权限、身份、schema 错误不盲目重复。
- 启动或休眠唤醒后检查错过任务，补采能恢复的日期。
- 19:30 前，最新候选日为上一交易日；休市日为最近交易日。
- 目标日选定后，不能因为缺数继续回退并称为本次成功。
- 同日已完成时返回“已是最新”；必要的交易日历核验除外，不重复全量取数。
- 手动、自动、回补共用队列。长历史回补在日任务边界让出执行机会，保证当日日更优先。
- 关闭网页但服务仍运行时继续调度；服务退出、电脑关机或休眠期间不承诺取数。

资金流官方更新时间为 19:00，19:30 只是尝试时间，发布仍取决于完备性检查。[官方更新时间](https://tushare.pro/document/1?doc_id=108)

首次运行顺序：

1. 检查依赖、时区、凭据与接口权限。
2. 优先取得最新目标日，形成可使用的三页快照。
3. 后台从早到晚回补近五年可验证历史。
4. 展示回补进度、可用起点与不可恢复缺口。
5. 原始数据按日处理，避免把五年全市场个股数据一次装入内存。

### 3.6 旧功能、安装与安全

旧申万功能和旧快照继续只读兼容。已查明，新源码首次更新目前依赖未随仓库发布的 SW2014 档案；新 schema 必须将其改为可选能力：

- 未安装：显示“尚未导入旧档案”，不阻塞新功能。
- 已安装且校验通过：提供原档案入口。
- 候选档案损坏：显示明确错误，不引用坏文件。
- 旧快照已声明包含的档案损坏时，仍按旧规则拒绝读取，不能借新规则绕过验证。

安装交付采用独立 `.venv`、完整依赖锁和 macOS 启动脚本，不能依赖 Codex 内置运行时或另一台电脑的虚拟环境。已有环境可沿用原项目支持的 Python 版本，最终锁文件须在选定 macOS 验收环境真实安装通过。

继续保留 loopback 监听、Host/Origin 校验、写请求 nonce、CSP、HTTPS 禁止重定向、凭据不落盘和无远程前端资源等边界。

导出提供两种明确操作：

- **当前视图 CSV**：对应当前批次、筛选、周期、口径与排序。
- **四分类 Excel**：对应同一批次和周期，保留四分类、口径说明、审计结果六个 Sheet；记录缺失状态，回读审计后原子生成。

### 3.7 全部列表三态排序

统一排序组件覆盖行业明细、资金排名、融合表、成分股、贡献明细、档案及数据质量列表。

规则固定为：

- 初始为页面定义的默认顺序。
- 点击同一表头：默认 → 升序 → 降序 → 默认。
- 换列从升序开始。
- 数值按原值、日期按日期、文本按中文排序规则比较。
- 空值在升降序中均置后；相等值以稳定标识确定次序。
- 资金排名字段不因显示排序变化而重新定义。
- 资金表默认净流入降序；估值表默认行业名称顺序；融合表默认行业代码顺序。
- 树形列表只在同级节点内排序。
- 先排序完整筛选结果，再分页。
- 保留键盘操作、排序方向提示及 `aria-sort`。

### 5.2 真实数据独立对照

从四套体系各取代表行业，对以下三种周期进行核验：

- 一个完整交易日。
- 一个完整自然周。
- 一个完整自然月。

独立复核直接读取冻结原始输入，使用不复用被测聚合函数的计算脚本，对照：

- 成员集合和去重结果。
- PE_TTM、PB 中位数及有效样本数。
- 日净流入、周月累计。
- 百分位及其样本边界。
- 页面、API 和导出的一致性。

THS 在尚未积累完整周月时，先验收“正确不可用”；积累完整证据后，再完成完整数值的真实对照。不能用伪造历史替代该项，也不能声称这一真实场景已经通过。

### 5.3 完成定义

项目完成必须同时满足：

- 五项原始需求及三轮确认内容均已实现。
- 新电脑从源码可以安装、启动、更新并访问三页。
- 四分类真实数据权限与可用范围已记录。
- 必需测试、独立数值对照、Chrome 操作链和恢复验证均有证据。
- 允许缺失的历史和指标正确显示原因，不被填零或冒充完整。
- 当前版本、依赖、文档和验收产物能够对应同一可复现源码基线。

本次对抗审查已覆盖最主要的错误来源：跨日混接、历史成员倒灌、官方与自建估值混用、资金口径替换、缺失当零、假层级、半批发布及首次安装依赖缺失。实施完成后的结论应以这些验收证据为依据。

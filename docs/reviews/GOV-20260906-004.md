## 使用与交付物

交付目录：`portable-dist/2.3.0-portable.1/`。完整步骤见该目录的 `README-PORTABLE.md`。

1. 选择对应 CPU 的 ZIP，完整解压到可写、较短的目录。
2. Mac 双击 `Start-Mac.command`，Windows 双击 `Start-Windows.cmd`。
3. 在终端无回显输入自己的 token；已有环境变量或本机 SDK token 时自动读取。不输入可只读浏览，token 不被持久保存。
4. 看到服务启动提示后，用 Chrome 手动访问 `http://127.0.0.1:8765`。
5. 等待更新达到终态后按 Ctrl+C 停止，再复制数据。首次导入和后续更新都只写本实例 `data/state`。

## 第一性原理与最小改动

跨机运行需要同时具备：目标架构的解释器、兼容的原生扩展、完整且能验证的数据，以及不依赖源电脑路径的启动入口。只压缩源码或复制本机 venv 不满足这些条件。

本轮只新增 `portable/` 外层能力。已有估值领域代码、网页、公式、身份映射、源合同/规格、旧 manifest 和正式数据未改。

- `prepare_runtime.py`：固定官方来源与 SHA-256、目标平台 wheel、许可证、静态二进制依赖检查。未复用 venv，仅复用经过锁定 SHA 和平台标签重新核验的原始 wheel。
- `build.py`：绑定 assets 的依赖锁和上游身份，校验完整 seed/legacy 库存、源文件字节，生成全新目录与 ZIP，不覆盖已有目的地。
- `launcher.py` 和双平台启动器：只使用私有 Python；`-I -B -X utf8`；先校验再加载 app；终端 token 仅进程内保存；原子导入 `data/state`，拒绝覆盖、目录逃逸及 junction。
- `verify_delivery.py`：用最终包内 Python，在中文、空格及 `&!` 临时路径独立验证和重建，不读取真实 token，禁止非 loopback 网络。
- `portable/tests/`、指南、来源清单和第三方说明：支持后续维护与目标机验收。

种子为前轮隔离验收的 `SWIVD2-RUN-20260904-001`，manifest SHA `cfb0e20fa13fa76ea8fbdc1ac611b246f0f48bebd87e1b80f92bb03f522dba6a`。复制形成便携实例，不代表原电脑正式 current 已切换。其 49 个冻结源文件与 app 对应字节一致；另保留原 v1 规格和完整历史档案。没有重写历史文件来消除历史 Mac 路径。
